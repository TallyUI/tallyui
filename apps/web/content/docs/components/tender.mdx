---
title: Tender
description: Tender is the sale's tender pane, laid out as WCPOS v2's, with a balance headline, payment legs with their status and void, a keypad, quick-cash chips and completion.
---

## Import

```tsx
import { Tender } from '@tallyui/components';
```

## Usage

```tsx
import { useSale } from '@tallyui/pos';
import { Tender } from '@tallyui/components';

// Inside a component under TaxProvider.
const sale = useSale(settings, { registerId, cashierRef });
<Tender sale={sale} />
```

Renders only during the sale's tender stage. The headline shows the total, or what remains once money is paid (pending legs never count), and any change. Each payment leg shows its method, amount and status, with Cancel payment where the method can void it. While a balance remains, the cashier picks Cash or Card terminal, types the amount on the keypad or presses a quick-cash chip (the exact amount, then the next 5, 10 and 50), and takes each leg in turn, so a sale can be split across several payments. Complete sale is enabled once nothing is due and no leg is in motion. Error, continuation and Back controls show as the sale state requires.

[TenderPane](/docs/components/tender-pane) is the same pane for a host that owns the tender reducer (`tenderReducer` from `@tallyui/pos`): it takes `sale`, `state` and `dispatch`.

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `sale` | `ReturnType<typeof useSale>` | required | The sale from [useSale](/docs/pos) |
| `tender` | `ReturnType<typeof useTender>` | own reducer | Share [useTender](/docs/components/use-tender)'s state and dispatch with Cart's unit picker |
| `methods` | `PaymentMethodDescriptor[]` | `defaultPaymentMethods()` | The methods offered: each manual-capture descriptor gets a tile and records its wire method (`cash` or `external`) plus its own id as `methodId`; other capture modes are not shown |
| `ledger` | `boolean` | `true` | Draws the payments ledger in the [TenderPane](/docs/components/tender-pane); pass `false` when Cart's `tenderLedger` shows it in the cart column |
| `back` | `boolean` | `true` | Draws the [TenderPane](/docs/components/tender-pane)'s Back button; pass `false` when the host leaves the tender stage itself, as WCPOS v2's phone checkout does; when money was taken here, Back opens the cancel-payment view first |
| `confirmVoid` | `boolean` | `false` | WCPOS v2's "Cancel this payment?" before a leg in the [TenderPane](/docs/components/tender-pane)'s ledger is voided: Cancel payment opens a question with the leg's amount ("Return €10.00 cash to the customer" for cash, else "Void €15.00 on Card terminal"), and the leg is voided only on confirm. Default off: Cancel payment voids at once |
| `beforeVoid` | `(leg: Payment) => boolean \| void \| Promise<boolean \| void>` | --- | Passed to the [TenderPane](/docs/components/tender-pane)'s ledger and its cancel-payment view: a host hook that runs before Cancel payment voids a leg (after Confirm with `confirmVoid`); the void waits for it, `false` or a throw keeps the leg, and the leg's Cancel payment is disabled while it runs |
| `afterVoid` | `(leg: Payment, voided: boolean) => void` | --- | Passed to the [TenderPane](/docs/components/tender-pane)'s ledger and its cancel-payment view, as `beforeVoid`: runs after a void that `beforeVoid` approved, with whether the leg was voided; `false` means the host reverses what it journalled |
| `beforeTake` | `(take: { methodId: string; amountMinor: number }) => boolean \| Promise<boolean>` | --- | Checks the selected method and the amount shown on Take before recording a leg. |
| `onTaken` | `(paymentId: string) => void` | --- | Reports the new leg's payment ID. |
| `offline` | `boolean` | `false` | Marks each method tile “Offline” without disabling it. |

Only a strict `true` from `beforeTake` takes payment. Any other answer, a throw or a rejection takes nothing. The host must always settle `beforeTake`, with its own timeout; the pane never times out on its own, and a `true` that arrives after the sale changed takes nothing. If `beforeTake` never settles, Take, Back, the method tiles, Complete sale and Cancel payment stay disabled on that order until the app reloads, even after tender is cancelled and restarted or the pane remounts. A zero-due cash settle writes off the remainder without calling either hook. `onTaken` fires only for new legs this pane records.

`beforeTake` must not move money itself: a `true` that is followed by no `onTaken` was not taken. While `beforeTake` is pending, the host must not move the sale inside a transition (`startTransition`, a form action): the pane cannot see such a move before it takes ([#1468](https://github.com/TallyUI/tallyui/issues/1468)).
