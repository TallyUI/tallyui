---
title: OrdersList
description: Recent orders and orders needing attention with sync details and retry actions
---

## Import

```tsx
import { OrdersList } from '@tallyui/components';
```

## Usage

```tsx
<OrdersList
  orders={orders}
  onRetry={(orderIds) => outbox.requeue(orderIds)}
  stuck={outbox.state.stuck}
/>
```

Renders Recent orders and a Needs attention section when applicable, with expandable line and payment details, sync status, and warnings. Eligible rejected orders have a Retry action that calls `onRetry`.

With `onReopen`, a sale the store refused with `coupon_invalid` or `total_mismatch` shows a "Reopen" button in Needs attention instead of no action. It calls `onReopen(order)`. When the coupons can't be carried at the amounts charged, the row offers "Reopen without the coupon: `amount` to collect", which calls `onReopen(order, { withoutCoupons: true })`; the till never drops the coupons on its own. A reopened sale stays in Needs attention, marked "Reopened as a parked sale.", with a Resume button when `onResume` is passed.

With `onCancelOnStore`, a Needs attention row whose refused sale left an order on the store with nothing paid shows "Cancel order on store". It asks first in a confirm dialog ("Keep order" or "Cancel order on store"), then calls `onCancelOnStore(order)`; the app wires `useOrderOutbox`'s `cancelOnStore`. While the call runs the button reads "Cancelling on store…" and a second press does nothing; a cancel that has not finished reads "Finish cancelling on store" and goes again with no dialog; when the store can't be reached the row says "Could not reach the store. Try again." until the next press. With the handler, such a row has no Retry, except a refusal for stock, whose Retry reads "Try the payment again". A row the store cancelled or removed leaves Needs attention. Once it is cancelled, a sale with cash legs also asks the cashier to record any cash they gave back as a pay-out.

With `onPayRestOnStore`, a Needs attention row whose refused sale left an order on the store that is part paid shows "Pay the rest on store". No money is taken: it records on the store the payments this till already took that the store is missing. A confirm dialog names each of those payments with its amount and says no money is taken now ("Keep as is" or "Record on store"), then calls `onPayRestOnStore(order)`; the app wires `useOrderOutbox`'s `payRestOnStore`. While the call runs the button reads "Recording on store…"; a recording that has not finished reads "Finish recording on store" and goes again with no dialog; when the store can't be reached the row says "Could not reach the store. Try again.". With the handler, a row with money recorded on the store has no Retry. A row the store shows as paid leaves Needs attention; one whose order is gone from the store stays, saying what was recorded on it.

With `onReverseOnStore`, a part-paid order can also offer "Give back and cancel" after "Pay the rest on store". The confirmation names every payment taken on the till and tells the cashier where to give it back. The till takes its manual payments off the store order, reads it again, and cancels only if nothing is still paid there. No money moves automatically: after cancellation, hand the cash back from the drawer or give the card payment back on the terminal. The till leaves that money out of its expected figures itself, so nothing is recorded as a pay-out. An unfinished attempt can be continued without confirming again. If the store refuses a step, the row stays in Needs attention and says which payments were taken off.

`OrderSyncNotices` renders one sale's sync notices on their own, for an app's own order screen: `<OrderSyncNotices order={order} stuck={outbox.state.stuck}>{retry}</OrderSyncNotices>`. Its `children` go where OrdersList puts Retry, between the notes and the store's warnings.

## Server order history

Pass the store's order history as `history` to show it in Recent with the till's own sales. Each row is platform-neutral, and the app maps its own store's orders into it:

```tsx
import { OrdersList, type OrderHistoryRow } from '@tallyui/components';

const history: OrderHistoryRow[] = storeOrders.map((order) => ({
  id: order.id,
  clientOrderId: order.clientOrderId, // the till's PosOrder id, when the till placed it
  reference: order.code,
  placedAt: order.placedAt,
  totalMinor: order.totalMinor,
  currency: order.currency,
  itemCount: order.itemCount,
  stateLabel: order.stateLabel,
}));

<OrdersList orders={orders} history={history} onRetry={(orderIds) => outbox.requeue(orderIds)} />
```

- **The outbox row wins.** A history row whose `clientOrderId` is the `id` of an order in `orders` is hidden while that order is there.
- **Newest first.** Recent merges outbox orders (by `createdAt`) and history rows (by `placedAt`). At equal times the outbox order comes first. A time that does not parse goes last.
- **Read-only.** A history row shows `Order <reference> · <n> items` and `<date> · <total> · <stateLabel>`, with `reference`, `itemCount` and `stateLabel` as given. It has no detail, no Retry and no warnings, and never appears under Needs attention.

Without `history`, the list renders exactly as before, with `orders` in the given order.

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `orders` | `PosOrder[]` | required | Orders shown in Recent and filtered into Needs attention |
| `onRetry` | `(orderIds: string[]) => Promise<number>` | required | Requeues rejected orders; a result of zero re-enables Retry immediately |
| `formatDate` | `(iso: string) => string` | `defaultFormatDate` | Formats order times; the default uses a medium date and short time, leaving unparseable values unchanged |
| `footer` | `ReactNode` | --- | App content rendered after the order sections |
| `stuck` | `OutboxState['stuck']` | --- | Outbox entries that make pending orders need attention and supply each order's waiting-since time |
| `history` | `OrderHistoryRow[]` | --- | The store's orders, shown read-only in Recent; a row is hidden while an outbox order has its `clientOrderId` as `id` |
| `onOpen` | `(row: PosOrder \| OrderHistoryRow) => void` | --- | Adds an Open button to each row, outbox order or history row, that passes it to the app |
| `onReopen` | `(order: PosOrder, options?: { withoutCoupons: true }) => Promise<void>` | --- | Adds Reopen to a Needs attention row the store refused with a reopenable code; the app wires `reopenRefusedOrder` |
| `onResume` | `(order: PosOrder) => void` | --- | Adds Resume to a reopened row in Needs attention; the app resumes the parked sale |
| `onCancelOnStore` | `(order: PosOrder) => Promise<SettleOutcome \| { kind: 'not_offered' }>` | --- | Adds Cancel order on store to a Needs attention row whose refused sale left an unpaid order on the store; the app wires `useOrderOutbox`'s `cancelOnStore` |
| `onPayRestOnStore` | `(order: PosOrder) => Promise<SettleOutcome \| { kind: 'not_offered' }>` | --- | Adds Pay the rest on store to a Needs attention row whose refused sale left a part-paid order on the store; the app wires `useOrderOutbox`'s `payRestOnStore` |
| `onReverseOnStore` | `(order: PosOrder) => Promise<SettleOutcome \| { kind: 'not_offered' }>` | --- | Adds Give back and cancel for a refused part-paid order; wire `useOrderOutbox`'s `reverseOnStore` |
