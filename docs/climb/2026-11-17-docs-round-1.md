# Docs and website hill climb, round 1 (2026-11-17)

## Brief

A panel judges TallyUI's docs and website (`apps/web`: the Fumadocs docs and the marketing pages).
Each judge reads the site built and served locally (`next start`, Playwright Chromium screenshots
at 1440 and 390 px, full page) and the MDX source, and scores seven criteria from 1 to 10, naming
the worst defect for each with its page and line. The three lowest criterion means are fixed, one
small spec and one PR each, and the panel then re-judges ([round 2](./2026-11-17-docs-round-2.md)).
A change that lowers the mean is reverted.

This round is a rerun: an earlier round 1 the same day was discarded. Open PR #859 (the
getting-started fixes in "Building a POS app → The database" and the docs index snippet) was
already in flight, so the judges named the worst defect outside it.

Judges:

| Judge | Persona | Model |
|---|---|---|
| a | A developer evaluating TallyUI for a new POS | Opus 5.5, read-only |
| b | A plugin author following getting started end to end | Opus 5.5, read-only |
| c | A connector author for a fourth backend | Opus 5.5, read-only |
| d | A docs editor: clarity, structure, dead links, stale names | Codex (GPT-6 Astra), read-only |

Three Opus judges plus Codex, not four plus Codex: the lane runs at most three subagents at once.

## The three lowest, and what was fixed

1. **Getting started works as written (4.0).** "Building a POS app": Sign in dropped `capabilities`,
   so the guide's own `finalizeOrder` call saw none; Selling used a `sessions` collection from
   nowhere and never stored the finalized order, which the outbox needs before it sends anything.
   Fixed in #878 (with #859 for "The database").
2. **Completeness of the API reference (4.75).** `useSale`, the hook every app sells with, had no
   reference: six component pages linked "useSale" to `/docs/pos`, which did not mention it. Fixed
   in the round's docs PR: a "Selling with useSale" section on `/docs/pos` (options, returned
   members, completion, one typechecked example).
3. **Examples (5.25).** The ProductCard usage passed an undefined `doc` and claimed a `'$'` default;
   SettingsRow used `Switch` without importing it, with props it does not have. Fixed in #878.
